# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Single-page wedding invitation — a **data-driven, reusable template** built with vanilla JS modules bundled by Vite. No framework, no backend. Content and UI text are in Spanish (Chilean locale, `es-CL`).

**`src/data/config.js` is the single source of truth.** All couple-specific data (names, dates, venue+coords, story+photos, parents/godparents, bank accounts, phones, texts, theme colors, SEO) lives in one exported `config` object. To reuse this invitation for another wedding, edit **only that file** — the HTML, rendered sections, theme, and SEO tags are all generated from it.

## Commands

- `npm run dev` — Vite dev server on port 3000 (host `0.0.0.0`, auto-opens browser). Serves from `src/`.
- `npm run optimize` — runs `build.js`: compresses media from `src/files/` into `src/assets/` (see Asset pipeline below). Mutates source files.
- `npm run build` — runs `optimize` then `vite build`, outputting to `dist/` (cleared each build).
- `npm run preview` — serves the production `dist/` build.

There are no tests, linter, or formatter configured.

## Architecture

`src/index.html` is the entry point (Vite `root` is `src/`). The HTML is a **shell with empty containers** — it holds no couple data. Two binding mechanisms fill it from `config`:
- `[data-text="path.to.value"]` / `[data-html="..."]` attributes → simple text nodes (resolved by dotted path in `config`; `data-text="nombresNovios"` is a special computed value). Filled by `bindTextos()` in `render.js`.
- Container `id`s (e.g. `#swiper-wrapper`, `#bendicion-grid`, `#info-banco`, `#whatsapp-buttons`, `#texto-regalos`, `#confirmacion-intro`) → repeated/list markup generated by dedicated functions in `render.js`.

`src/js/index.js` is the single bootstrap. Order matters: it calls `aplicarTema()` immediately, then on `DOMContentLoaded` runs **`renderInvitacion()` first** (it creates the DOM nodes), then the feature initializers that attach to those generated nodes. Adding a feature: create a module in `src/js/`, export an init function, call it after `renderInvitacion()` in `index.js`. Modules locate their own DOM nodes and no-op if absent.

Module responsibilities:
- `render.js` — generates all dynamic content from `config` (slides, bendición grid, gift paragraphs, bank blocks, WhatsApp buttons, RSVP intro, audio source). **Must run before** swiper/helpers/sendConfirmMessage, which depend on the nodes it creates.
- `theme.js` — `aplicarTema()` writes `config.tema` colors/fonts into the CSS variables on `:root` (`--dorado`, `--azulOscuro`, fonts, etc.).
- `countdown.js` + `fechaUtils.js` — date display and live countdown. `fechaUtils.js` re-exports the dates from `config.fecha` (don't hardcode dates here — edit `config`).
- `calendar.js` — "Agregar al calendario": builds a Google Calendar link and a downloadable `.ics` from `config`, injected into `#calendar-actions`. Uses floating local time (no timezone offset) so the event shows at the configured hour for everyone.
- `swiperSetup.js` — photo carousel (Swiper). Lazily initialized via `IntersectionObserver` on `.historia`; singleton-guarded.
- `reveal.js` — fade-in of sections on scroll. The hidden initial state is gated behind a `.js-reveal` class on `<html>` (added only when JS runs) and disabled under `prefers-reduced-motion`, so without JS everything stays visible.
- `iconos.js` — Lottie animations from `src/assets/animations/*.json` into containers by `id`.
- `animations.js` — GSAP float/rotate loop on the dresscode image.
- `musicPlayer.js` — background audio; starts muted, unmuted via the welcome modal (autoplay policy), with play/pause toggle.
- `mapChooser.js` (+ `mapChooser.css`) — overlay to open the venue in Google Maps or Waze; coords/label passed from `index.js` (sourced from `config.lugar`).
- `sendConfirmMessage.js` — builds WhatsApp RSVP links from `data-name`/`data-phone` on `.contact-button` elements, using `config.confirmacion.plantillaMensaje`.
- `helpers.js` — clipboard copy for bank-detail blocks (`.bloque-banco`).

### SEO / Open Graph

WhatsApp/social crawlers don't run JS, so OG/meta tags must be static in the HTML. `vite.config.js` has an `inyectarSeo()` plugin (`transformIndexHtml`) that **imports `config` and replaces `%SEO_*%` placeholders** in `index.html` at build *and* dev time — keeping SEO config-driven. `og:image` becomes absolute only when `config.seo.url` is set (fill it in when deploying, otherwise the share preview image won't load for WhatsApp).

Styling is one large hand-written file: `src/css/styles.css`. Theme colors/fonts are CSS variables in `:root` overwritten at runtime by `theme.js`. `mapChooser.css` is imported via JS.

## Asset pipeline (`build.js`)

Source media goes in `src/files/` (committed originals); optimized output goes in `src/assets/` (also committed, consumed by the site). `npm run optimize`:
- Empties `src/assets/img` and `src/assets/music`, then regenerates them.
- Converts JPG/PNG in `src/files/img/` → WebP (imagemin); copies other formats (SVG, existing WebP) as-is.
- **Rewrites image extensions to `.webp` in `src/index.html` and `src/css/styles.css` in place** (regex on `./assets/img/...` references) — be aware this mutates tracked source files.
- Compresses MP3s in `src/files/music/` to 80k bitrate (ffmpeg) into `src/assets/music/`.

So reference images in HTML/CSS as `./assets/img/<name>.webp`. To change a photo, add the original to `src/files/img/` and re-run optimize.
